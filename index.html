1. Basi Numeriche & Notazione Posizionale
C Literals: 0b, 0, 0x
Un numero è una sequenza di cifre il cui peso dipende dalla posizione e dalla base: il computer lavora in base 2, noi usiamo la base 16 per scriverla in modo compatto.

📖 Spiegazione estesa: cos'è una base numerica

Un sistema numerico posizionale rappresenta un valore come somma di cifre moltiplicate per potenze della base. Nel sistema decimale (base 10) il numero 345 significa 3×10² + 4×10¹ + 5×10⁰. La stessa idea vale per qualsiasi base b: la cifra in posizione i (contando da destra, partendo da 0) vale cifra × bⁱ.

Perché il computer usa il binario

I circuiti elettronici distinguono in modo affidabile due soli stati (tensione bassa/alta, passa/non passa corrente). Ogni stato è un bit (0 o 1). Con n bit si ottengono 2ⁿ combinazioni diverse: 8 bit (un byte) ne danno 256.

Perché esadecimale e ottale

Leggere lunghe sequenze di 0 e 1 è faticoso e soggetto a errori. Poiché 16 = 2⁴, ogni cifra esadecimale corrisponde esattamente a 4 bit: il byte 11010110 si spezza in 1101 e 0110, quindi 0xD6. L'ottale (8 = 2³) raggruppa invece i bit a tre a tre.

Conversioni fondamentali

  • Binario → decimale: somma i pesi (1, 2, 4, 8, 16…) delle posizioni in cui c'è un 1.
  • Decimale → binario: dividi ripetutamente per 2 e leggi i resti dal basso verso l'alto (oppure sottrai le potenze di 2 più grandi possibili).
  • Binario ↔ esadecimale: raggruppa i bit a gruppi di 4 partendo da destra e sostituisci ogni gruppo con la sua cifra.

In linguaggio C

Il compilatore riconosce i prefissi: 0x1F (esadecimale), 017 (ottale: attenzione, uno zero iniziale cambia il significato!) e, come estensione ormai comune (standard C23), 0b1010 (binario). Con printf si usano %d (decimale), %x/%X (esadecimale) e %o (ottale).

Binario (Base 2) 0b...

Cifre: {0, 1}
  • Linguaggio nativo dei transistor & flip-flop
  • 1 byte = 8 bit (256 stati distinti)
  • Operatori C bitwise: &, |, ^, ~, <<, >>

Esadecimale (Base 16) 0x...

Cifre: 0-9, A-F
  • 1 cifra HEX = esattamente 4 bit (1 nibble)
  • 2 cifre HEX = esattamente 1 byte (es. 0xFF = 255)
  • Formati printf: %x (minuscolo), %X (maiuscolo), %p (puntatori)

Ottale (Base 8) 0...

Cifre: 0-7
  • 1 cifra OTT = esattamente 3 bit
  • Attenzione in C: prefisso 0 (es. int a = 012; vale 10 decimale!)
  • Usato nei permessi POSIX Unix (es. chmod 0755)

2. Interi Senza Segno (Unsigned)
unsigned int, uint8_t, %u
Interi senza segno: tutti gli n bit sono pesi positivi, valori da 0 a 2ⁿ−1; oltre il massimo si ricomincia da 0.

📖 Spiegazione estesa: come si rappresenta un intero non negativo

La rappresentazione senza segno (unsigned) è la più semplice: ogni bit ha un peso pari a una potenza di 2 e il valore del numero è la somma dei pesi dei bit uguali a 1. In un byte i pesi, da sinistra a destra, sono 128, 64, 32, 16, 8, 4, 2, 1; il valore massimo è quindi 255 (tutti i bit a 1).

Intervalli di valori

Con n bit si rappresentano i numeri da 0 a 2ⁿ−1: 0…255 con 8 bit, 0…65 535 con 16 bit, 0…4 294 967 295 con 32 bit. Non esistono numeri negativi: se serve il segno si usa il complemento a due (categoria successiva).

Somma e riporto

L'addizione binaria funziona come quella in colonna: 1+1 = 10 (scrivo 0, riporto 1). Se il riporto esce dal bit più a sinistra il risultato non entra più nello spazio disponibile: si ha overflow (o carry), e il risultato è corretto solo modulo 2ⁿ. Esempio a 8 bit: 250 + 10 = 260, ma 260 mod 256 = 4.

In linguaggio C

I tipi unsigned char, unsigned short, unsigned int (o uint8_t, uint16_t, uint32_t di <stdint.h>) usano questa codifica. Per gli unsigned lo standard garantisce il comportamento modulare, quindi il wraparound è definito. Si stampano con %u (decimale) e %x (esadecimale). Una conseguenza pratica: una variabile unsigned è sempre ≥ 0, quindi un ciclo con condizione i >= 0 non termina mai.

Rappresentazione Posizionale Pura

V = Σ (bᵢ × 2ⁱ)
  • Tutti gli n bit concorrono al valore positivo assoluto
  • Range con n bit: [0, 2ⁿ - 1]
  • 8 bit: 0 .. 255 | 16 bit: 0 .. 65.535 | 32 bit: 0 .. 4.294.967.295

Comportamento di Overflow in C

Aritmetica Modulo 2ⁿ
  • Nessun Undefined Behavior: garantito dallo standard C
  • Se si supera il massimo, riparte da 0 (wraparound)
  • Esempio: uint8_t x = 255; x++; → x = 0

📖 Approfondimento: La Memoria e i Tipi Unsigned in C

Nel linguaggio C, un intero senza segno dichiara esplicitamente al compilatore che tutti i bit allocati per la variabile devono essere interpretati come pesi positivi di potenze di 2. Con l'introduzione dello standard C99 e dell'header <stdint.h>, il programmatore può selezionare tipi a dimensione prefissata garantita su qualsiasi architettura (ad esempio uint8_t per 8 bit, uint16_t per 16 bit, uint32_t per 32 bit e uint64_t per 64 bit). 

// Esempio di gestione unsigned ed overflow in C
#include <stdio.h>
#include <stdint.h>

int main() {
    uint8_t contatore = 250;
    for (int i = 0; i < 8; i++) {
        printf("Valore: %u (Hex: 0x%02X)\n", contatore, contatore);
        contatore++; // Al superamento di 255 fa wraparound a 0
    }
    return 0;
}
⚠️ Attenzione ai loop infiniti in C:
Un errore tipico dei principianti è scrivere for (uint8_t i = 10; i >= 0; i--). Poiché un tipo unsigned è sempre ≥ 0 per definizione matematica, la condizione i >= 0 non sarà mai falsa: quando i raggiunge lo zero, decrementandolo diventa 255, creando un ciclo infinito!

3. Interi con Segno & Complemento a Due
int, int8_t, int16_t, %d
Per avere numeri negativi si usa il complemento a due: il bit più a sinistra pesa −2ⁿ⁻¹; si nega un numero invertendo i bit e sommando 1.

📖 Spiegazione estesa: numeri negativi e complemento a due

Per rappresentare numeri negativi serve riservare parte dei bit al segno. Esistono vari metodi (modulo e segno, complemento a uno), ma i computer moderni usano quasi universalmente il complemento a due, perché permette di eseguire somme e sottrazioni con lo stesso identico circuito.

Come si interpreta

È una codifica posizionale in cui il bit più significativo ha peso negativo: in un byte i pesi sono −128, 64, 32, 16, 8, 4, 2, 1. Così 11111011 vale −128+64+32+16+8+2+1 = −5. Se il bit più a sinistra è 0 il numero è positivo (o zero), se è 1 è negativo.

Come si calcola l'opposto di un numero

  1. Scrivi il valore assoluto in binario sul numero di bit voluto (es. 5 → 00000101).
  2. Inverti tutti i bit (11111010).
  3. Somma 1 (11111011 = −5).

La stessa procedura converte anche da negativo a positivo.

Intervallo e anomalie

Con n bit si coprono i valori da −2ⁿ⁻¹ a +2ⁿ⁻¹−1: con 8 bit da −128 a +127. L'intervallo è asimmetrico: esiste −128 ma non +128, quindi negare −128 restituisce ancora −128. Esiste un solo zero (00000000).

Estensione di segno

Passando da meno bit a più bit (ad esempio da 8 a 16) bisogna replicare il bit di segno a sinistra: −2 passa da 11111110 a 1111111111111110. Aggiungere zeri trasformerebbe il numero in +254.

In linguaggio C

I tipi int, short, int8_t… usano il complemento a due su tutte le piattaforme comuni. Si stampano con %d. Attenzione: l'overflow di un tipo con segno è comportamento indefinito per lo standard C (diversamente dagli unsigned), e mescolare signed e unsigned in un confronto può dare risultati sorprendenti.

Regola del Peso Negativo (MSB)

MSB = -2ⁿ⁻¹
  • Il bit più a sinistra ha valore posizionale -2ⁿ⁻¹
  • Per 8 bit: peso del bit 7 è -128!
  • Range con n bit: [-2ⁿ⁻¹, +2ⁿ⁻¹ - 1] (8 bit: -128 .. +127)

Algoritmo di Negazione

-X = ~X + 1
  • 1. Inverti tutti i bit (NOT bitwise ~)
  • 2. Aggiungi 1 al risultato
  • Unico zero (00000000), niente +0 e -0 separati
  • L'ALU esegue la sottrazione usando lo stesso sommatore: A - B = A + (~B + 1)

📖 Approfondimento: Perché l'Informatica usa il Complemento a Due?

Nei primi calcolatori storici si tentò l'approccio "Modulo e Segno" (1 bit per il segno e i restanti bit per il valore assoluto). Questo creava due gravissimi difetti ingegneristici: la presenza di due zeri distinti (+0 e -0, costringendo i circuiti logici a fare doppi controlli) e la necessità di progettare circuiti separati per la sottrazione.

Nel Complemento a Due, l'addizione tra numeri positivi e negativi funziona spontaneamente con la medesima algebra hardware. Inoltre, l'intervallo è asimmetrico: con 8 bit possiamo andare da -128 a +127. Questo introduce una famosa anomalia in C: abs(-128) non può produrre +128 su un int8_t, provocando overflow! 

// Sottrazione a livello hardware in C
#include <stdio.h>
int main() {
    char a = 7;    // 00000111
    char b = 10;   // 00001010 -> Negato e +1: 11110110 (-10)
    char r = a - b; // ALU fa: 00000111 + 11110110 = 11111101 (-3)
    printf("Risultato: %d\n", r); // Stampa: -3
    return 0;
}

4. Numeri Reali: Standard IEEE 754
float (32 bit), double (64 bit), %f
I numeri reali si memorizzano in virgola mobile (IEEE 754): segno, esponente con bias e mantissa. Ampio intervallo, precisione limitata.

📖 Spiegazione estesa: la virgola mobile IEEE 754

Per rappresentare numeri molto grandi o molto piccoli (e con la parte frazionaria) si usa una forma simile alla notazione scientifica, ma in base 2: (−1)^S × 1.M × 2^(E−bias). Lo standard IEEE 754 definisce come distribuire i bit.

I tre campi del float a 32 bit

  • Segno S (1 bit): 0 positivo, 1 negativo.
  • Esponente E (8 bit): memorizzato con bias 127 (spiegato nel dettaglio sotto).
  • Mantissa M (23 bit): la parte frazionaria dopo la virgola. Il numero è sempre normalizzato nella forma 1.xxx, quindi l'1 iniziale è implicito e non si memorizza.

Il double segue la stessa idea con 1 + 11 + 52 bit e bias 1023.

Il sistema del Bias (esponente polarizzato)

L'esponente reale di un numero in notazione scientifica binaria può essere sia positivo (numeri grandi, es. 2⁵) sia negativo (numeri piccoli, es. 2⁻³). Invece di usare il complemento a due per l'esponente, IEEE 754 sceglie la notazione polarizzata (con bias): al valore reale dell'esponente si somma una costante fissa chiamata bias, pari a 2^(k−1) − 1 (dove k è il numero di bit dell'esponente).

  • Per float (8 bit di esponente): bias = 127. Formula: E_memorizzato = E_reale + 127 (e inversamente E_reale = E_memorizzato − 127).
  • Per double (11 bit di esponente): bias = 1023.
  • Esempi: esponente reale 0 → 0 + 127 = 127 (01111111₂); esponente +3 → 3 + 127 = 130 (10000010₂); esponente −4 → −4 + 127 = 123 (01111011₂).
  • Intervallo normale: i valori 0 e 255 (tutti 0 o tutti 1) sono riservati a casi speciali (zero, denormalizzati, ±Inf, NaN). Restano quindi i valori da 1 a 254, che rappresentano esponenti reali da −126 a +127.
  • Perché si usa il bias? Trasforma tutti gli esponenti in interi senza segno (sempre ≥ 0). In questo modo la CPU può confrontare l'ordine di grandezza di due float positivi confrontando i loro bit come semplici interi unsigned, rendendo l'hardware più veloce!

Conversione della parte fratta (frazionaria) in binario

Così come la parte intera usa potenze positive di 2, i bit dopo la virgola rappresentano potenze negative di 2: il primo bit vale 2⁻¹ = 0,5, il secondo 2⁻² = 0,25, il terzo 2⁻³ = 0,125, il quarto 2⁻⁴ = 0,0625 e così via.

Per convertire una parte frazionaria decimale (compresa tra 0 e 1) in binario si usa il metodo delle moltiplicazioni successive per 2:

  1. Moltiplica per 2 la parte frazionaria.
  2. La parte intera ottenuta (che sarà sempre 0 oppure 1) è la prossima cifra binaria dopo la virgola.
  3. Prendi la nuova parte frazionaria rimasta e ripeti dal passo 1, finché la frazione diventa 0 (conversione esatta) oppure finché hai riempito i 23 bit della mantissa (troncamento/arrotondamento).
  • Esempio esatto (0,625): 0,625 × 2 = 1,25 → bit 1 (resta 0,25); 0,25 × 2 = 0,50 → bit 0 (resta 0,50); 0,50 × 2 = 1,00 → bit 1 (resta 0, stop). Risultato: 0,625₁₀ = 0,101₂ (infatti 0,5 + 0,125 = 0,625).
  • Esempio periodico (0,1): 0,1 × 2 = 0,2 (0) → 0,2 × 2 = 0,4 (0) → 0,4 × 2 = 0,8 (0) → 0,8 × 2 = 1,6 (1, resta 0,6) → 0,6 × 2 = 1,2 (1, resta 0,2)… da qui il ciclo 0011 si ripete all'infinito: 0,1₁₀ = 0,0001100110011…₂. Per questo in C 0.1f non è mai esatto al 100%!

Come si converte un numero completo (es. 12,375)

  1. Converti la parte intera (12 = 1100) e la frazione (0,375 = 0,011, moltiplicando per 2 e prendendo la parte intera).
  2. Scrivi 1100,011 e normalizza: 1,100011 × 2³.
  3. Esponente memorizzato = 3 + 127 = 130 = 10000010.
  4. Mantissa = 10001100000000000000000; segno = 0.

Limiti e casi speciali

Molte frazioni decimali (come 0,1) sono periodiche in binario e vengono quindi approssimate: 0.1 + 0.2 == 0.3 in C è falso. Un float ha circa 7 cifre decimali significative, un double circa 15–16. Esponente tutto a 1 con mantissa 0 indica ±infinito, con mantissa diversa da 0 indica NaN (non un numero); esponente 0 serve per lo zero e i numeri denormalizzati.

In linguaggio C

Si usano i tipi float e double, con %f (o %e, %g) in printf. Mai confrontare due reali con ==: si confronta la differenza con una piccola tolleranza.

Anatomia del Float 32-bit (Single Precision)

(-1)ˢ × (1.M) × 2^(E - 127)
S (1)
Esponente (8 bit)
Mantissa / Frazione (23 bit)
  • S (Segno): 0 = positivo, 1 = negativo
  • Esponente: Polarizzato con Bias = 127 (E_reale = E_memorizzato - 127)
  • Mantissa: Parte frazionaria con 1 implicito (1.frazione)

Sistema del Bias (Esponente Polarizzato)

E = E_reale + 127 (Bias)
  • Perché: evita il bit di segno nell'esponente; confronti più veloci in hardware (solo interi unsigned)
  • Range 8 bit: 1..254 → E_reale ∈ [−126, +127] (0 e 255 riservati)
  • Esempi: E_reale = 0 → 127 | +3 → 130 | −4 → 123 (double: bias = 1023)

Conversione Parte Fratta (× 2)

f × 2 → Parte Intera = Bit
  • Pesi frazionari: 2⁻¹ (0.5), 2⁻² (0.25), 2⁻³ (0.125), 2⁻⁴ (0.0625)…
  • Algoritmo: moltiplica per 2; prendi la parte intera (0/1); ripeti sulla nuova frazione finché = 0 (o 23 bit)
  • Es. 0.625: ×2=1.25 → ×2=0.5 → ×2=1.0 → 0.101₂

Casi Speciali & Trabocchetti C

0.1 + 0.2 != 0.3
  • Esponente = 255: Se mantissa = 0 → +Inf / -Inf (divisione per zero). Se mantissa ≠ 0 → NaN (0/0)
  • Esponente = 0: Numeri denormalizzati e zeri con segno (+0.0f e -0.0f)
  • Le frazioni decimali come 0.1 sono numeri periodici in binario, quindi approssimate!

📖 Approfondimento: Come ragiona la FPU di un computer

A differenza degli interi, che sono esatti fino al loro limite di capienza, i numeri in virgola mobile (definiti dallo standard IEEE 754-1985) scambiano l'accuratezza assoluta con una dinamica di scala gigantesca. Un float a 32 bit può rappresentare numeri fino a circa $3.4 \times 10^{38}$ e piccoli fino a $1.4 \times 10^{-45}$, ma ha soltanto 7 cifre decimali di precisione significativa. 

// Ispezione a basso livello dei bit di un float in C tramite union
#include <stdio.h>
#include <stdint.h>

typedef union {
    float f;
    struct {
        uint32_t mantissa : 23;
        uint32_t esponente : 8;
        uint32_t segno : 1;
    } campi;
    uint32_t raw;
} FloatInspector;

int main() {
    FloatInspector fi;
    fi.f = -12.375f;
    printf("Float: %f\n", fi.f);
    printf("Segno: %u | Esp: %u (dec) | Mantissa: 0x%X | Hex Raw: 0x%08X\n",
           fi.campi.segno, fi.campi.esponente, fi.campi.mantissa, fi.raw);
    return 0;
}

5. Codifica Caratteri: ASCII & ASCII Esteso
char, 'A' == 65, %c
Ogni carattere ha un codice numerico: ASCII usa 7 bit (128 simboli), le estensioni a 8 bit ne aggiungono altri 128 ma sono incompatibili tra loro.

📖 Spiegazione estesa: come si codifica il testo

Il computer sa memorizzare solo numeri, quindi per il testo serve una tabella di corrispondenza tra caratteri e codici. La più diffusa è l'ASCII (American Standard Code for Information Interchange), che usa 7 bit e definisce 128 codici.

Organizzazione della tabella ASCII

  • 0–31 e 127: caratteri di controllo non stampabili (NUL = 0, tabulazione = 9, a capo LF = 10, CR = 13…).
  • 32: lo spazio.
  • 48–57: le cifre '0'…'9'. Attenzione: il carattere '5' ha codice 53, non 5.
  • 65–90: le lettere maiuscole 'A'…'Z'.
  • 97–122: le lettere minuscole 'a'…'z'. Differiscono dalle maiuscole di 32, cioè dal solo bit 5.

ASCII esteso

Poiché un byte ha 8 bit, restavano liberi altri 128 codici (128–255). Ogni paese li ha usati per le proprie lettere accentate e simboli, dando origine a tabelle diverse (ISO 8859-1 «Latin-1» per l'Europa occidentale, ISO 8859-5 per il cirillico, Windows-1252…). Lo stesso byte può quindi significare caratteri diversi a seconda della tabella: aprire un file con la codifica sbagliata produce testo illeggibile (mojibake). Fu uno dei motivi per cui nacque Unicode.

In linguaggio C

Il tipo char è un piccolo intero (di solito 1 byte): 'A' è semplicemente il numero 65. Perciò si può fare aritmetica sui caratteri: c - '0' converte una cifra-carattere nel suo valore, c + 1 passa alla lettera successiva, c | 0x20 rende minuscola una lettera maiuscola. Una stringa è un array di char terminato dal byte nullo '\0' (codice 0). Con printf: %c stampa il carattere, %d il suo codice. Il tipo char può essere signed o unsigned a seconda della piattaforma: per byte grezzi conviene unsigned char.

ASCII Standard (7 bit)

128 Caratteri (0 .. 127)
  • 0 .. 31: Controlli non stampabili (NUL=0, LF=10 '\n', CR=13, TAB=9)
  • '0' .. '9': 0x30 .. 0x39 (48 .. 57)
  • 'A' .. 'Z': 0x41 .. 0x5A (65 .. 90)
  • 'a' .. 'z': 0x61 .. 0x7A (97 .. 122)

Il Trucco del Bit 5 in C & ASCII Esteso

'a' - 'A' = 32 (0x20 = 00100000₂)
  • La sola differenza tra maiuscola e minuscola è il bit 5!
  • Maiuscolo in C: c & ~0x20 | Minuscolo: c | 0x20
  • ASCII Esteso (8 bit, 256 car.): ISO 8859-1 (Latin-1) aggiunge lettere accentate (è, à, ò). Limite: frammentazione incompatibile!

📖 Approfondimento: In C i "Caratteri" sono Interi a 8 bit!

Uno dei concetti più liberatori per uno studente di C è comprendere che il tipo char non è affatto un "testo magico", bensì semplicemente un numero intero memorizzato su 1 byte. Scrivere 'A' nel codice sorgente è letteralmente identico per il compilatore a scrivere il numero 65. Di conseguenza, su un carattere si possono eseguire tutte le operazioni aritmetiche e logiche: 

// Trucchi di manipolazione caratteri tipici del C
#include <stdio.h>

int main() {
    char c = '7';
    int cifra = c - '0'; // Converte il char '7' nel numero intero 7! (55 - 48 = 7)
    
    char minuscola = 'g';
    char maiuscola = minuscola & ~0x20; // Spegne il bit 5 -> diventa 'G'

    printf("Valore numerico: %d, Lettera: %c\n", cifra, maiuscola);
    return 0;
}
⚠️ Trabocchetto C: 'char' è signed o unsigned?
Lo standard C non stabilisce se il tipo char base sia con segno o senza segno: dipende dall'architettura (su x86 è solitamente signed da -128 a 127, su ARM spesso unsigned da 0 a 255). Se si usano caratteri estesi ISO-8859 con codice > 127 (es. 'è' = 232) e il char è signed, il valore risulterà negativo se stampato con %d! Per gestire byte grezzi si raccomanda sempre unsigned char o uint8_t.

6. Codifica Universale: Solo UTF-8
Multibyte char[], Code Points
Unicode dà un codice a ogni carattere del mondo; UTF-8 lo scrive con 1–4 byte, ed è identico all'ASCII per i primi 128 simboli.

📖 Spiegazione estesa: Unicode e UTF-8

Unicode è uno standard che assegna a ogni carattere di ogni sistema di scrittura (latino, greco, cirillico, arabo, cinese, simboli matematici, emoji…) un numero univoco chiamato code point, scritto U+XXXX (esempi: U+0041 = 'A', U+00E8 = 'è', U+20AC = '€'). Unicode però definisce solo l'elenco dei caratteri: per memorizzarli in byte serve una codifica, e la più usata è UTF-8.

Come funziona UTF-8

UTF-8 usa un numero variabile di byte (da 1 a 4) a seconda del code point. I bit iniziali del primo byte dicono quanti byte compongono il carattere; i byte successivi iniziano sempre con 10.

  • U+0000–U+007F: 1 byte, 0xxxxxxx (identico ad ASCII)
  • U+0080–U+07FF: 2 byte, 110xxxxx 10xxxxxx
  • U+0800–U+FFFF: 3 byte, 1110xxxx 10xxxxxx 10xxxxxx
  • U+10000–U+10FFFF: 4 byte, 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx

Le «x» vanno riempite con i bit del code point, da destra a sinistra. Esempio per '€' (U+20AC = 0010 0000 1010 1100): servono 3 byte → 11100010 10000010 10101100 = E2 82 AC.

Perché ha avuto successo

  • Compatibilità con ASCII: un file ASCII è già un file UTF-8 valido.
  • Efficienza: i testi in alfabeto latino occupano poco spazio (1 byte per lettera, 2 per le accentate).
  • Auto-sincronizzazione: dal primo byte si capisce se si è all'inizio di un carattere, quindi un errore non corrompe tutto il resto del testo.

In linguaggio C

Il C tratta le stringhe come sequenze di byte: strlen("Caffè") restituisce 6, perché la 'è' occupa 2 byte (C3 A8). Quindi strlen conta i byte, non i caratteri visibili, e s[i] non è necessariamente un carattere intero. Per contare i veri caratteri si saltano i byte di continuazione, cioè quelli del tipo 10xxxxxx ((byte & 0xC0) == 0x80).

La Regola dei Prefissi Bit in UTF-8

1 .. 4 Byte a Lunghezza Variabile
  • 1 Byte (ASCII puro): 0xxxxxxx (0 .. 127)
  • 2 Byte (Europei/Greci/Arabi): 110xxxxx 10xxxxxx
  • 3 Byte (Asiatici, Euro €): 1110xxxx 10xxxxxx 10xxxxxx
  • 4 Byte (Emoji, simboli rari): 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx

Proprietà Ingegneristiche Chiave

Self-Synchronizing & ASCII-Compliant
  • Retrocompatibilità 100%: Qualsiasi file ASCII puro è GIÀ un file UTF-8 valido senza modifiche!
  • Byte di continuazione: Iniziano sempre con 10xxxxxx. Se perdi la sincronizzazione nel flusso, ti riagganci immediatamente al prossimo carattere.
  • Zero spreco di spazio rispetto a UTF-32.

📖 Approfondimento: La Trappola di UTF-8 in C (`strlen` vs Caratteri)

Il linguaggio C classico è nato prima di Unicode: per il C un char equivale a 1 byte. In UTF-8, tuttavia, 1 carattere visivo può richiedere da 1 a 4 byte! Questo genera bug diffusissimi tra gli sviluppatori: 

// Dimostrazione della natura multibyte di UTF-8 in C
#include <stdio.h>
#include <string.h>

int main() {
    char testo[] = "Caffè"; // In UTF-8 la 'è' occupa 2 byte: 0xC3 0xA8
    
    printf("Testo: %s\n", testo);
    printf("Numero di byte (strlen): %zu\n", strlen(testo)); // Stampa 6, NON 5!
    printf("Dimensione buffer (sizeof): %zu\n", sizeof(testo)); // Stampa 7 (+ '\0')
    
    // Se accediamo a testo[4], otteniamo solo il byte di testa 0xC3, non l'intera 'è'!
    printf("Byte 4 in Hex: 0x%02X\n", (unsigned char)testo[4]);
    printf("Byte 5 in Hex: 0x%02X\n", (unsigned char)testo[5]);
    return 0;
}
💡 Come contare i veri caratteri UTF-8 in C?
Basta scorrere l'array di byte e contare solo i byte che NON iniziano con 10xxxxxx (ovvero (byte & 0xC0) != 0x80). In questo modo i byte di continuazione vengono ignorati e si ottiene l'esatto numero di glifi!

Code Point Unicode ↔ Sequenza Byte UTF-8
Esempio 1: Lettera ASCII ('Z' - U+005A) Facile (1 Byte)
Unicode: U+005A ('Z')
⇄
UTF-8: 0x5A (Bin: 01011010₂)
  1. Poiché il codice è ≤ 127 (0x7F), si usa il template a 1 byte: 0xxxxxxx.
  2. Il codice binario di 90 è 1011010. Inserito nello schema diventa 01011010. Identico ad ASCII!
Esempio 2: Lettera accentata ('è' - U+00E8) Intermedio (2 Byte)
Unicode: U+00E8 ('è')
⇄
UTF-8: 0xC3 0xA8 (2 byte in memoria)
  1. Code Point 0x00E8 in binario: 00000000 11101000.
  2. Richiede 2 byte: template 110xxxxx 10xxxxxx (11 bit utili totali).
  3. Prendi gli ultimi 6 bit (101000) → secondo byte: 10101000 (0xA8).
  4. Prendi i 5 bit precedenti (00011) → primo byte: 11000011 (0xC3).
  5. Risultato in C: la lettera 'è' occupa 2 celle di memoria consecutive: 0xC3 e 0xA8.
Esempio 3: Simbolo Valuta Euro ('€' - U+20AC) Avanzato (3 Byte)
Unicode: U+20AC ('€')
⇄
UTF-8: 0xE2 0x82 0xAC (3 byte in memoria)
  1. Code point 0x20AC in binario a 16 bit: 0010 0000 1010 1100.
  2. Template a 3 byte: 1110xxxx 10xxxxxx 10xxxxxx.
  3. Byte 3: 10 + 101100 = 10101100₂ (0xAC).
  4. Byte 2: 10 + 000010 = 10000010₂ (0x82).
  5. Byte 1: 1110 + 0010 = 11100010₂ (0xE2).
